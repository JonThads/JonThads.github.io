Prompt Engineering with the CARE Framework

8 Nov 2026 · 5 min read · Jon Thaddeus Laguitao

AI / PromptingPrompt Engineering
Save this note for another look.

Most of us use AI in one way or another, from drafting essays and emails to generating images and writing code. But how does an AI assistant know what we want? Through prompts.

What a prompt is

A prompt is an instruction we give to an AI to get the result we want, like “Generate me an image of a cat” or “Please give me a 500-word essay about the history of Napoleon Bonaparte.” For many everyday tasks, an instruction like that is enough.

When simple is not enough

Some work is more serious or detail-oriented: fixing a particular bug in a production codebase, writing a spiel for a specific show segment, or drafting emails for different audiences such as the C-suite, upper management, supervisors, and technical teams. A one-line instruction leaves the AI guessing about all the details that matter, and you end up reworking the output again and again.

What prompt engineering is

Prompt engineering is the skill of writing prompts that get customized, useful results with minimal rework after the first response.

It helps to know why this works. AI models are probabilistic: they generate likely responses instead of looking up one correct answer. A vague prompt leaves a lot of room for the model to guess. A specific prompt narrows that room and guides the model toward the answer you actually need.

The CARE framework

There are many prompting frameworks. The one I use is CARE, which stands for:

  • Context: what you want to achieve, and the background the AI needs.
  • Action: the specific steps you want it to take.
  • Result: what a good outcome looks like, so you can tell whether it worked.
  • Example: a sample that shows the style, format, or quality you are after.

CARE in action: the cat

Start with the plain prompt:

Generate me an image of a cat.

You will get a cat, but probably a generic one. Now the same request, written with CARE: 

CONTEXT
I want an image of a cat similar to my black cat: a male Persian, about
4 years old, curled up asleep in a loaf position, dreaming about eating
a fish. My cat's photo is attached.

ACTION
1. Make the image realistic, not obviously AI-generated.
2. Use the attached photo as a reference for my cat's appearance and color.
3. Export the image as a .png file.
4. Show it here in the chat first so I can review it.
5. After I approve it, save it to my D: drive if you have file access;
   if you don't, tell me the file name and format to use.

RESULT
A realistic, recognizable image of my cat that is ready for me to post
on Facebook.

EXAMPLE
[Attached: a sample photo showing the realistic style I want.]

Each part does a different job. Context says what and why. Action says how and in what order. Result defines done. Example shows the target. The output is an image made for you, not a generic AI cat.

Workbench note

Whether the AI can save a file depends on the tool. Chat-only assistants cannot write to your drive, so write the Action for what your tool can really do.

CARE at work

The same four parts help with everyday engineering and QA tasks. Here is a short illustration of turning rough notes into a clear bug report. It is a sample prompt, not a real ticket. 

CONTEXT
I am a QA engineer. Below are my rough notes from testing the checkout
page in a staging environment. The audience is the developer who will
fix it.

ACTION
1. Read the notes and separate what I observed from what I assume.
2. Write a bug report with: title, steps to reproduce, expected result,
   actual result, and environment.
3. List any information still missing instead of guessing it.

RESULT
A report a developer can reproduce without asking me follow-up
questions. No speculation about the cause.

EXAMPLE
[Paste one of your team's well-written bug reports here.]

NOTES
[Paste rough notes here.]

Asking the AI to list missing information, rather than fill it in, is a small Action that prevents confident but invented details.

Lessons and next experiment

  • Be specific about the outcome. “Good” means different things to different readers.
  • Keep each part short. Too much context can bury the instruction.
  • Review the first response and refine the prompt, not just the output.
  • Never paste confidential or personal data into an AI tool unless you are allowed to.

My next question: which of the four parts changes the quality of the output the most? I would like to test that by removing one part at a time and comparing the results.
